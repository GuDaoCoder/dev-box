# DevBox 发布检查表

## 版本与代码

- [ ] 改动先提交到 `dev`，PR 检查通过后合并到 `main`；未直接推送开发提交到 `main`。
- [ ] 发布标签指向已合并到 `main` 的提交；PR 合并后才创建并推送标签。
- [ ] 工作区、桌面包、Tauri 和 Cargo 版本一致。
- [ ] `CHANGELOG.md` 已更新，版本符合 SemVer。
- [ ] 发布标签为 `app-v<version>`，并通过 `scripts/check-release-tag.mjs`。
- [ ] 工作区无意外的未提交文件，测试私钥未用于正式产物。

## 自动检查

- [ ] `pnpm check:release` 通过。
- [ ] `pnpm test:e2e` 通过中英文、键盘、Tab 菜单和性能冒烟用例。
- [ ] 深浅主题正文、次要文字和焦点强调色通过 WCAG 对比度检查。
- [ ] JS 原始总量不超过 450 KiB，CSS 原始总量不超过 60 KiB。
- [ ] ZIP 恶意路径、重复文件、数量、压缩比、签名篡改和身份伪造回归通过。

## 目标平台验证

- [ ] macOS：DMG 安装、首次启动、内置工具、ZIP 安装、覆盖升级和移除应用。
- [ ] Windows：MSI/安装程序安装、首次启动、内置工具、ZIP 安装、覆盖升级和卸载。
- [ ] Windows 和 macOS 均确认中文/英文、深色/浅色、键盘焦点、右键菜单和未签名警告。
- [ ] 安装前后的插件数据保留/删除行为与用户选择一致。

## 产物

- [ ] Release workflow 的 Windows 双版本和 macOS 双架构任务全部成功。
- [ ] 产物名包含应用版本、系统和架构；安装包可下载且非空。
- [ ] 记录每个安装包的 SHA-256。
- [ ] 未签名开发产物明确标注，正式发布前完成代码签名与 macOS 公证。
- [ ] 从干净环境抽查下载、安装、启动和卸载后再发布。

当前自动化能生成 Windows 和 macOS 安装包；Linux 暂不发布。真正的安装、升级和卸载仍需在对应系统执行本表的人工验证。
