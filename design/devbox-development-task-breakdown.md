# DevBox MVP 开发任务拆解

> 输入文档：`devbox-architecture-design.md`、`devbox-ui-design-spec.md`
> 更新日期：2026-09-18
> 仓库：`dev-box` 平台、`devbox-tools` 官方工具
> 产品范围：插件平台、在线/离线安装、JSON、Timestamp、Encoding、UUID/Hash
> 明确排除：SQL Formatter、JWT、正则测试、HTTP Client、Java 编辑器/Runner

## 1. 里程碑与交付顺序

| 里程碑 | 状态 | 目标 | 主要交付 | 退出条件 |
|---|---|---|---|---|
| M0 工程基线 | 已完成 | 建立可持续开发工程 | workspace、Tauri、CI、测试 | 工程可检查和构建 |
| M1 Shell 与平台骨架 | 已完成 | 打通平台最小闭环 | App Shell、i18n、Plugin SDK、IPC、SQLite | Foundation 插件可激活、调用 Host、保存设置 |
| M2 插件分发基础 | 已完成，待验收 | 建立安全、可恢复的运行时安装能力 | 包格式、签名、Installer、隔离 WebView、在线/离线安装 | 同一签名示例包可在线与离线安装、启停、更新、回退、卸载 |
| M3 官方通用工具 | 待开发 | 用独立仓库验证真实插件交付 | `devbox-tools`、JSON、Timestamp、Encoding、UUID/Hash | 四个工具均以签名包安装并双语可用 |
| M4 Plugin Center 体验 | 待开发 | 完善用户可见的插件管理 | 在线目录、更新、来源/权限、恢复、开发者模式 | 插件管理关键流程中英文 E2E 通过 |
| M5 稳定性与发布 | 待开发 | 达到三平台可分发标准 | 安全加固、性能、文档、安装包 | 发布检查表全部通过 |

必须按 M2 → M3 → M4 推进。没有经过统一 Installer 的工具包不得作为 M3 完成结果；在线与离线安装不得维护两套验证实现。

## 2. 优先级、规模与完成定义

- **P0**：阻塞 MVP，缺失时不得进入下一里程碑。
- **P1**：MVP 应完成，可缩减体验但不能破坏安全和恢复能力。
- **P2**：可延后优化，不阻塞首版。
- **S**：约 0.5–1 天；**M**：约 1–2 天；**L**：约 2–4 天。

所有任务统一完成定义：

1. 功能、类型、失败路径和恢复路径均已实现。
2. 用户可见文案同时提供 `zh-CN` 和 `en-US`。
3. 单元/组件测试覆盖成功、非法输入和边界条件。
4. 涉及包解析、文件写入、签名、权限时，Rust Host 必须独立校验。
5. 在线和离线来源进入同一安装服务，不通过 UI 逻辑复制安全规则。
6. 无未说明的 lint、类型、测试、构建失败或安全警告。
7. 对应 schema、错误码、任务状态和变更说明已更新。


## 14. MVP 发布检查表

- [ ] Windows、macOS、Linux 均能安装、启动、升级和卸载 DevBox。
- [ ] 同一个官方签名包可通过在线目录和离线文件安装。
- [ ] 篡改、未知发布者、撤销密钥和不兼容插件均被拒绝。
- [ ] 插件包无法通过路径穿越、链接或压缩炸弹写出插件目录。
- [ ] 更新失败和应用异常退出不会破坏当前可用插件版本。

- [ ] 在线目录不可用时，已安装插件与离线安装仍正常工作。
- [ ] 未签名插件默认拒绝；开发者模式有持久醒目标识且不授予特权能力。

- [ ] 无 P0/P1 阻塞缺陷，用户文档和安全说明提供中英文版本。
